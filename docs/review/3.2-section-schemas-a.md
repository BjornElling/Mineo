# Punkt: 3.2 Section-schemas A (stamdata, satser, aarsloen, faellesAarsloen)

**Dato:** 2026-06-11
**Filer gennemgået:** `src/schemas/formSchemas/sections/stamdataSchemas.ts`, `satserSchemas.ts`, `aarsloenSchemas.ts`, `faellesAarsloenSchemas.ts`
**Tests kørt:** `npx vitest run src/__tests__/schemas` (formSchemas + eoFileSchema + base) — grønt.

## Fund og rettelser

Ingen fejl fundet. Schemaerne er korrekte, fail-closed og forward/backward-tolerante:

- **stamdata** — alle felter optional; kanonisk `'' → undefined`-mønster på enum (`skadestype`). Cross-field `superRefine` (skadedato før fødselsdato) afgiver issues på begge felter. `.strict().superRefine(...)`-wrapperen bryder ikke strip-/optional-pipelinen ved load (verificeret mod `stripUnknownFieldsBySchema` og `eoFileDataInnerSchema.optional()`-stien).
- **satser** — kun `aargang` (valgt satsår) persisteres; sats-/rentetabeller er programdata og holdes ude af `.eo`. Korrekt afgrænsning.
- **aarsloen** — de påkrævede felter (`loenperiode`, `tableData`, `omregningTilFuldtAar`, `fuldLoenUnderFerie`, `retTilSjetteFerieuge`, `loenPaaHelligdage`) har konservative load-defaults der matcher en ny tom sag, så en ældre `.eo` uden dem ikke fejler hele sektionen. Bevidst ikke settings-styret (persistence-contract forbyder injektion af device-lokale settings under load). Dækket af eksisterende round-trip-tests.
- **faellesAarsloen** — `aslAarsloen`/`ealAarsloen` som `positiveAmountValue` (afviser 0, negativ, -0). Snapshot-input sammensættes først efter per-sektions-validering.

## Tilfældighedsfund

Ingen ud over det allerede noterede under 3.1.

## Sammenfatning

- Ingen rettelser nødvendige; alle fire sektioner følger de fastlagte mønstre (optional-enum-normalisering, fail-closed beløb, forward/backward-tolerante defaults).
- Konvergeret med fundamentet. Ingen UI/UX- eller beregningslogik-ændringer.
