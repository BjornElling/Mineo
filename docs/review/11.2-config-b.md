# Punkt: 11.2 Config B

**Dato:** 2026-06-19
**Filer gennemgået:** `src/config/regulatoryRates.ts`, `src/config/indskudteLoentillaeg.ts`, `src/config/appTheme.ts`, `src/config/tableTheme.ts` (+ alle konsumenter via repo-bred søgning). Krydsref 6.2 (`indskudteLoentillaeg`) og `src/settings/appSettingsSchema.ts` (`themeMode`).
**Tests kørt:** `npm run typecheck` (grøn), `npm run typecheck:test` (grøn), `npm run lint` på ændrede filer (grøn), `npx vitest run src/__tests__/config/ src/__tests__/settings/ …` (18 filer / 183 tests grøn).

## Fund og rettelser

1. **Dobbelt sandhedskilde for tema-tilstand** — Medium (type-sikkerhed/konvergens). Lokation: `src/config/appTheme.ts:4` (`export type AppThemeMode = 'light' | 'dark'`) vs. `src/settings/appSettingsSchema.ts` (`themeMode: z.enum(['light','dark'])`). To uafhængige definitioner af samme værdiunion uden kobling; drift-risiko hvis den ene udvides (fx ny tema-tilstand) uden den anden. Bryder "Én sandhedskilde" + Zod-autoritet (AGENTS.md). **✅ Rettet:** `appSettingsSchema.ts` ejer nu et kanonisk `themeModeEnum = z.enum(['light','dark'])` og udleder `AppThemeMode = z.infer<…>`. `appTheme.ts` importerer typen og re-eksporterer den (så eksisterende `import { AppThemeMode } from '../config/appTheme'` i test fortsat virker). Rent type-niveau; ingen adfærdsændring (typecheck + alle tests grønne).

2. **`TIMER_TIL_MAANED_FAKTOR` (regulatoryRates.ts)** — Lav. Single source of truth for time↔måned-faktoren (160,33), brugt i `eoSharedUtils.ts` (begge konverteringsretninger + display). Literalen `160.33` optræder ellers kun som rå satsdata i `data/RLTN/rltnLoenSatser.ts` (tilfældigt samme tal, ikke en parallel faktor-definition). ⏭ Ingen handling.

3. **`indskudteLoentillaeg.ts` — Store Bededag wired, Særligt ferietillæg forberedt** — Lav (bevidst). `STORE_BEDEDAG_START`/`STORE_BEDEDAG_PCT` er aktivt brugt i lønudviklings-/reguleringsmotorerne (`loenudviklingBeregning.ts`, `reguleringsPresentation.ts`, `loenindkomstSatser.ts`, `overenskomstReguleringShared.ts`, dokumentgenerering). `SAERLIGT_FERIETILLAEG_*`, `STORE_BEDEDAG_SATSTRAPPE` og `resolveIndskudtLoentillaegPct` er pt. kun test-dækkede — det er den **planlagte fælles model** for indskudte tillæg (jf. memory `saerligt-ferietillaeg-planned` og fil-header §"FORBEREDT"). ⏭ **Ikke rettet** — bevidst forberedt domæne-struktur ejet af brugeren (beregningslogik); må ikke fjernes som "dødkode". Bemærket: når Særligt ferietillæg kobles ind, bør både det og Store Bededag gå gennem `resolveIndskudtLoentillaegPct(satstrappe, …)` (i dag bruger Store Bededag skalar-konstanterne direkte), så de to følger ét mønster.

4. **Hardkodet `'2005-01-01'` i `SAERLIGT_FERIETILLAEG_SATSTRAPPE`** — Lav. Kommentaren siger den holdes i sync med `DATE_2005_01_01` i `dateRanges.ts`. Bekræftet: `DATE_2005_01_01` er bevidst **ikke** eksporteret fra `dateRanges.ts` (modul-intern), så import er ikke mulig; sync er dokumenteret, ikke kode-håndhævet. Da satstrappen ikke er i produktion endnu, er konsekvensen pt. nul. ⏭ Ikke rettet — acceptabelt design; genbesøges sammen med fund 3 når feature implementeres.

5. **`appTheme.ts` `buildTheme`** — Lav. Eneste tema-bygger (ingen konkurrerende `createTheme` i produktion; kun test-lokale). Forbruges i `App.tsx` (`buildTheme(settings.themeMode)`) og `MinProcesrenteApp.tsx` (`buildTheme('light')`). ⏭ Ingen handling.

6. **`tableTheme.ts`** — Lav. `getMuiTableStyles`, `getHtmlTableStyles` og `htmlTableHeaderStyles` er hver anvendt (MUI-tabeller hhv. native HTML-tabeller); ingen overlappende parallel tabel-styling-helper. ⏭ Ingen handling.

## Tilfældighedsfund

- **(14.2-kandidat, allerede dækket)** Når Særligt ferietillæg implementeres, bør Store Bededag omlægges til `resolveIndskudtLoentillaegPct` så indskudte tillæg deler ét opslag-mønster (jf. fund 3). Noteret her; ikke et selvstændigt udskudt-fund da det indgår i den planlagte feature.

## Sammenfatning

- **Rettelse:** Tema-tilstands-typen har nu én sandhedskilde (Zod-enum i `appSettingsSchema.ts`); `appTheme.ts` udleder den i stedet for at duplikere unionen.
- Resten af Config B er ren og fuldt anvendt; `TIMER_TIL_MAANED_FAKTOR`, `buildTheme` og tabel-helpers er kanoniske uden duplikering.
- `indskudteLoentillaeg`s Særligt ferietillæg-del er bevidst forberedt (planlagt beregning, brugerejet) og bevares uændret; ingen åbne godkendelsespunkter for 11.2.
