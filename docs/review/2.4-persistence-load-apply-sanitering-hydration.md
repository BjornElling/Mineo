## Fund og rettelser

1. **[Høj — brugervendt, godkendt] Preflight talte harmløs felt-oprydning som "fejl"** — ✅ Rettet (godkendt af bruger 2026-06-11). `failedCount` var `loadIssues.length` og inkluderede `strippedUnknownField`/`migratedField`; preflight-dialogen ("Filen kan ikke indlæses fuldt ud", "Fejlede: N", "Hvad fejlede") blev vist ved enhver forskel, også forventet forward/backward-kompatibel feltoprydning. Nu skelnes der i `fileLoad.ts` mellem **ægte fejl** (`sectionDropped`, `unknownSection` — data der IKKE kunne indlæses) og **informationelt** (`strippedUnknownField`, `migratedField`). Kun ægte fejl udløser preflight og tæller som "Fejlede"; filer hvor alt kan indlæses (kun oprydning) loader stille. Informationelle issues logges (`logWarning`) til diagnose. **Brugervalg:** "Indlæs stille, advar kun ved ægte fejl". Test opdateret (`fileLoad.normalLoad.test.ts`).

2. **[Høj] Session-hydration kasserede cleanup ved storage-læsefejl** — ✅ Rettet. En `readSessionStorageValue`-throw på én nøgle returnerede tidligere straks med `keysToRemove: []` og afbrød de resterende sektioner + invalidDrafts-læsning. Nu sættes et `storageReadFailed`-flag og løkken fortsætter fail-closed; de allerede indsamlede `keysToRemove` bevares (cleanup, §8.7), og en storage-læsefejl-notice prioriteres ved retur.

3. **[Medium] `isPersistedData`/`isEnvelope` accepterede arrays som `data`** — ✅ Rettet. Begge guards afviser nu `Array.isArray(data)` (en persisteret sektion / envelope-data er altid et objekt). Korrupt `{...,data:[]}` klassificeres nu korrekt.

4. **[Lav] Duplikeret return + unsafe cast i `persistenceLoadApply`** — ✅ Rettet. PWA-metadata-grenen samlet til én `if/else` med ét return. Cast i `buildAuthoritativeLoadSnapshot` er nu kommenteret som load-bearing-safe alene pga. downstream Zod-re-validering i `replaceAllPersistedData`.
